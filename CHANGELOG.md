# Changelog

All notable changes to Scenaria. Versions follow `MAJOR.MINOR.PATCH`; before 1.0 a minor version may change behaviour.

## Unreleased

- **Landing page** (`site/`, `npm run build:site`): one static page in German and English with the drawings of the introduction and the real Simple view as a live example in the browser. It loads nothing from other servers and sets no cookies. Published only when a person starts the “Landing page” workflow.
- The example to try out is split into `DemoStage` (the example itself) and `Demo` (the overlay in the dashboard), so the landing page shows the same example.

## 0.9.24 — a dashboard without loose ends

For people who open Scenaria for the first time. Checked by clicking through every view in a browser.

**New:**
- **Introduction in five pictures** (saving, looking, going back, who approves, getting started), in German and English. It opens on the first visit and can be started again at any time: at the top of the help, in the Simple view of an empty project, and under More. The pictures are built in; nothing is loaded from anywhere.
- **Try it on an example:** the real Simple view on an invented project with three small tasks (look, go back, undo). Nothing reaches the server, so nothing in the person's project or files changes.

**Changed:**
- **Chat, forecasts, the forecast audit and “Ask the oracle” appear only once a language model is set up**, marked as experimental. Without a model nobody runs into functions that cannot work; the settings say what a model unlocks, and a help topic that needs one says so and leads to the settings.
- **The Simple view no longer shows boxes that only say “not measurable”:** progress appears for a task with approved criteria, the AI's memory once something was measured (or there is a stop or a warning).
- **Connecting an AI from a locked window** opens the unlocked window directly at the settings (`then=settings`, a fixed list; nothing else can ride on the link), and the locked note says in plain words what happens.
- **German instead of English leftovers:** titles of automatic saves, the automatic checks of a step, reasons of the gate, the kinds of log entries and the common log entries, the Windsurf note in the settings. Chat and oracle explain a failed model call with reason and fix, like the forecasts.
- **One name per thing:** the analysis is called “Analyse / Analysis” in every view (was also “Projekt-Check”), the help says “Regeln & Meilensteine (Fixpunkte)” as the button does, and the German README names the third view “Steuerung” as the dashboard does.

**For developers:** `ui/src/Tour.tsx`, `TourArt.tsx`, `tourText.ts`, `Demo.tsx`, `demoData.ts` (generated by `scripts/make-demo-data.mjs` from the real engine), `localize.ts`; tests in `test/simpleui.test.mjs`.

## 0.9.23 — security and release preparation

**Security (update recommended):**
- The project's `verifyCommand` (a shell command from `.scenaria/config.json`, a file agents can edit) ran for any caller of `POST /api/verify`, the tool `scenaria_verify` or `scenaria verify --run`, with the rights of the Scenaria process. It now runs only when the person starts it at an interactive terminal and confirms its text; for every other caller the result says "not run".
- Git hooks and git settings placed in `.scenaria/shadow.git` (or, with the mirror on, in the project's own `.git`) ran when Scenaria saved, compared or restored. Every git call now switches off hooks, `core.fsmonitor`, the alternate-refs command, signing programs and the `ext::` transport; the shadow repository's config is reduced to what `git init` writes before git reads it, and a change is logged.
- A step's folder name read from a step file can no longer lead out of `.scenaria/`; "open as folder" only shows the folder (macOS: `open -R`) and never launches an application bundle.
- Seven known vulnerabilities in dependencies fixed (`zod` ≥ 4.6.6 and the HTTP packages of the MCP SDK); `npm audit` reports none.

**Release:**
- Release files come with `SHA256SUMS`; `install.sh` and `install.ps1` check the download against it and stop on a mismatch.
- CI also builds and runs the tests on Windows (informational until the suite is green there), checks the dashboard's types and fails on a known vulnerability in what users install.
- The server reported an old version number (0.9.17); it now matches the package, and a test keeps it so.
- New: `SECURITY.md`, `CONTRIBUTING.md`, `docs/DEVELOPMENT.md`, `docs/KNOWN-LIMITS.md`, `docs/GUIDE.md` (the full reference that used to be the README), automatic dependency updates.

**Changed behaviour:** `scenaria_verify {runCommand: true}` and `POST /api/verify {runCommand: true}` no longer run the command (a check "command: not run" is recorded). Library callers pass `commandBy: "person"` when the person started it.
